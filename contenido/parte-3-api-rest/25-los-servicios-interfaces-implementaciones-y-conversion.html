25 Los servicios: interfaces, implementaciones y conversión

Las capas y las inyecciones

ServicioRepositorios que inyectaPara qué los necesita
EditorialServiceImplIEditorialRepository, ILibroRepositoryGuardar y buscar editoriales, y contar sus libros antes de borrar.
AutorServiceImplIAutorRepositoryGuardar autores y recorrer sus libros.
LibroServiceImplILibroRepository, IEditorialRepository, IAutorRepositoryConvertir los ids que llegan en entidades reales y asociarlas al libro.

¿Por qué LibroServiceImpl inyecta tres repositorios y no llama a IEditorialService?

LibroServiceImpl necesita transformar claves foráneas (editorialId, autoresIds) en instancias de entidades persistentes (Editorial, Autor) para establecer las relaciones en la base de datos. Si llamáramos a IEditorialService, solo nos entregaría un EditorialResponseDTO (por la regla que prohíbe exponer entidades en los contratos de servicio), y un DTO no puede asociarse a una relación JPA de Libro. Por eso el servicio accede directamente a los repositorios.

El cocinero necesita el tomate de verdad, no una foto del tomate. Va a la nevera (el repositorio), no al camarero.

Cómo se escribe un método de la interfaz del servicio

La interfaz (IMedicoService, ILibroService…) es el contrato: la lista de cosas que el servicio sabe hacer, sin decir cómo. Cada línea es un método sin cuerpo, que termina en ;. El cuerpo lo escribe después la clase que la implementa (MedicoService, LibroServiceImpl), con @Override encima de cada método. El controlador solo conoce la interfaz.

Tomemos un método del ejercicio del hospital y leámoslo por partes:

MedicoResponseDTO crear(MedicoRequestDTO dto);
ParteQué esCómo se decide
MedicoResponseDTOEl tipo de retorno: lo que el servicio le devuelve al controlador.¿Qué tiene que enseñar el controlador al cliente? Al crear, el médico recién creado (con su id), así que su ResponseDTO.
crearEl nombre del método.Un verbo que diga la acción: crear, obtener, listarPorHospital, eliminar.
(MedicoRequestDTO dto)Los parámetros: lo que el servicio necesita recibir para hacer su trabajo.Para crear, los datos que manda el cliente: su RequestDTO. Para buscar o borrar, basta el Long id.
;Fin del método, sin llaves ni cuerpo.En una interfaz solo se declara. El código va en la implementación.

La regla de oro: en la interfaz solo aparecen DTO y tipos simples (Long, boolean, List…), nunca entidades. Así el controlador no llega a tocar JPA. Casi todos los servicios siguen este patrón:

OperaciónFirma típicaPor qué así

Buscar unoXResponseDTO obtener(Long id);Basta el id. Si no existe, el servicio lo indica (por ejemplo, devolviendo null u Optional.empty()).
ListarList<XResponseDTO> listarPorHospital(Long hospitalId);Varios resultados: una lista, que puede estar vacía.
Comprobar algoboolean tieneConsultas(Long id);Una pregunta de sí o no, que el controlador usa para decidir el código (por ejemplo, 409).
Borrarvoid eliminar(Long id);No hay nada que devolver (ver más abajo).

¿Por qué eliminar puede ser void?

void significa que el método no devuelve nada. Al borrar no hay ningún dato que enseñar: el recurso ya no existe, y la respuesta HTTP correcta es 204 No Content, que va sin cuerpo. Así que el servicio no necesita devolver un DTO.

¿Y cómo sabe entonces el controlador si había que responder 404 o 409? Preguntándolo antes de borrar: primero comprueba si existe (si no, 404), después si se puede borrar (si no, 409), y solo entonces llama a eliminar. Es lo que hace el ejercicio del hospital. La solución de la biblioteca de este paso elige otra forma: su eliminar devuelve un int que cuenta qué pasó (1, 0 o -1). Las dos valen; la de void es la más sencilla de leer.

El «idioma» entre el servicio y el controlador

En esta solución los servicios no lanzan excepciones para los casos normales: devuelven un valor que cuenta qué pasó, y el controlador lo traduce a un código HTTP.

La pieza central: POST /api/libros de principio a fin

Se debe poder explicar sin mirar apuntes. El servicio resuelve la editorial por su id, resuelve cada autor, crea la ficha técnica, ensambla el Libro (con addAutor para dejar los dos lados coherentes), lo guarda y lo convierte en LibroResponseDTO. El controlador lo devuelve en un ResponseEntity con 201 y la cabecera Location.

package edu.rico.biblioteca.service;

import java.util.List;
import java.util.Optional;

import edu.rico.biblioteca.dto.FichaLibroDTO;
import edu.rico.biblioteca.dto.LibroRequestDTO;
import edu.rico.biblioteca.dto.LibroResponseDTO;

public interface ILibroService {
    LibroResponseDTO crear(LibroRequestDTO dto);

    Optional<LibroResponseDTO> obtenerPorId(Long id);

    Optional<List<LibroResponseDTO>> listarPorEditorial(Long editorialId);

    Optional<LibroResponseDTO> actualizarFicha(Long libroId, FichaLibroDTO fichaDTO);

    Optional<LibroResponseDTO> asociarAutor(Long libroId, Long autorId);

    boolean desasociarAutor(Long libroId, Long autorId);
}
package edu.rico.biblioteca.service.impl;

import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import edu.rico.biblioteca.dto.AutorResumenDTO;
import edu.rico.biblioteca.dto.EditorialResumenDTO;
import edu.rico.biblioteca.dto.FichaLibroDTO;
import edu.rico.biblioteca.dto.LibroRequestDTO;
import edu.rico.biblioteca.dto.LibroResponseDTO;
import edu.rico.biblioteca.entity.Autor;
import edu.rico.biblioteca.entity.Editorial;
import edu.rico.biblioteca.entity.FichaLibro;
import edu.rico.biblioteca.entity.Libro;
import edu.rico.biblioteca.repository.IAutorRepository;
import edu.rico.biblioteca.repository.IEditorialRepository;
import edu.rico.biblioteca.repository.ILibroRepository;
import edu.rico.biblioteca.service.ILibroService;

@Service
public class LibroServiceImpl implements ILibroService {

    @Autowired
    private ILibroRepository libroRepo;

    @Autowired
    private IEditorialRepository editorialRepo;

    @Autowired
    private IAutorRepository autorRepo;

    @Override
    @Transactional
    public LibroResponseDTO crear(LibroRequestDTO dto) {
        // 1. Resolver la Editorial
        Optional<Editorial> editorialOpt = editorialRepo.findById(dto.editorialId());
        if (editorialOpt.isEmpty()) {
            throw new IllegalArgumentException("La editorial con ID " + dto.editorialId() + " no existe");
        }

        Libro libro = new Libro(dto.titulo());
        libro.setEditorial(editorialOpt.get());

        // 2. Resolver Autores
        if (dto.autoresIds() != null && !dto.autoresIds().isEmpty()) {
            for (Long autorId : dto.autoresIds()) {
                Optional<Autor> autorOpt = autorRepo.findById(autorId);
                if (autorOpt.isEmpty()) {
                    throw new IllegalArgumentException("El autor con ID " + autorId + " no existe");
                }
                libro.addAutor(autorOpt.get());
            }
        }

        // 3. Resolver Ficha Técnica (1:1)
        if (dto.ficha() != null) {
            FichaLibro ficha = new FichaLibro(dto.ficha().isbn(), dto.ficha().paginas(), dto.ficha().anio());
            libro.setFicha(ficha);
        }

        Libro guardado = libroRepo.save(libro);
        return mapearAResponseDTO(guardado);
    }

    @Override
    @Transactional(readOnly = true)
    public Optional<LibroResponseDTO> obtenerPorId(Long id) {
        Optional<Libro> opt = libroRepo.findByIdConRelaciones(id);
        if (opt.isEmpty()) {
            return Optional.empty();
        }
        return Optional.of(mapearAResponseDTO(opt.get()));
    }

    @Override
    @Transactional(readOnly = true)
    public Optional<List<LibroResponseDTO>> listarPorEditorial(Long editorialId) {
        if (!editorialRepo.existsById(editorialId)) {
            return Optional.empty();
        }

        List<Libro> libros = libroRepo.findByEditorialId(editorialId);
        List<LibroResponseDTO> listaDTO = new ArrayList<>();
        for (Libro l : libros) {
            listaDTO.add(mapearAResponseDTO(l));
        }
        return Optional.of(listaDTO);
    }

    @Override
    @Transactional
    public Optional<LibroResponseDTO> actualizarFicha(Long libroId, FichaLibroDTO fichaDTO) {
        Optional<Libro> opt = libroRepo.findById(libroId);
        if (opt.isEmpty()) {
            return Optional.empty();
        }

        Libro libro = opt.get();
        FichaLibro ficha = libro.getFicha();

        if (ficha == null) {
            ficha = new FichaLibro();
            libro.setFicha(ficha);
        }

        ficha.setIsbn(fichaDTO.isbn());
        ficha.setPaginas(fichaDTO.paginas());
        ficha.setAnio(fichaDTO.anio());

        Libro guardado = libroRepo.save(libro);
        return Optional.of(mapearAResponseDTO(guardado));
    }

    @Override
    @Transactional
    public Optional<LibroResponseDTO> asociarAutor(Long libroId, Long autorId) {
        Optional<Libro> libroOpt = libroRepo.findById(libroId);
        Optional<Autor> autorOpt = autorRepo.findById(autorId);

        if (libroOpt.isEmpty() || autorOpt.isEmpty()) {
            return Optional.empty();
        }

        Libro libro = libroOpt.get();
        Autor autor = autorOpt.get();

        libro.addAutor(autor);
        Libro guardado = libroRepo.save(libro);
        return Optional.of(mapearAResponseDTO(guardado));
    }

    @Override
    @Transactional
    public boolean desasociarAutor(Long libroId, Long autorId) {
        Optional<Libro> libroOpt = libroRepo.findById(libroId);
        Optional<Autor> autorOpt = autorRepo.findById(autorId);

        if (libroOpt.isEmpty() || autorOpt.isEmpty()) {
            return false;
        }

        Libro libro = libroOpt.get();
        Autor autor = autorOpt.get();

        libro.removeAutor(autor);
        libroRepo.save(libro);
        return true;
    }

    // Conversión manual entre Entity y DTO (sin librerías externas)
    private LibroResponseDTO mapearAResponseDTO(Libro l) {
        EditorialResumenDTO edDTO = null;
        if (l.getEditorial() != null) {
            edDTO = new EditorialResumenDTO(l.getEditorial().getId(), l.getEditorial().getNombre());
        }

        List<AutorResumenDTO> autoresDTO = new ArrayList<>();
        if (l.getAutores() != null) {
            for (Autor a : l.getAutores()) {
                autoresDTO.add(new AutorResumenDTO(a.getId(), a.getNombre()));
            }
        }

        FichaLibroDTO fichaDTO = null;
        if (l.getFicha() != null) {
            fichaDTO = new FichaLibroDTO(l.getFicha().getIsbn(), l.getFicha().getPaginas(), l.getFicha().getAnio());
        }

        return new LibroResponseDTO(l.getId(), l.getTitulo(), edDTO, autoresDTO, fichaDTO);
    }
}
EditorialServiceImpl.java y su interfaz 
package edu.rico.biblioteca.service;

import java.util.Optional;

import edu.rico.biblioteca.dto.EditorialRequestDTO;
import edu.rico.biblioteca.dto.EditorialResponseDTO;

public interface IEditorialService {
    EditorialResponseDTO crear(EditorialRequestDTO dto);

    Optional<EditorialResponseDTO> obtenerPorId(Long id);

    // Devuelve: 1 = borrado con éxito (204), 0 = no existe (404), -1 = conflicto, tiene libros (409)
    int eliminar(Long id);
}
package edu.rico.biblioteca.service.impl;

import java.util.Optional;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import edu.rico.biblioteca.dto.EditorialRequestDTO;
import edu.rico.biblioteca.dto.EditorialResponseDTO;
import edu.rico.biblioteca.entity.Editorial;
import edu.rico.biblioteca.repository.IEditorialRepository;
import edu.rico.biblioteca.repository.ILibroRepository;
import edu.rico.biblioteca.service.IEditorialService;

@Service
public class EditorialServiceImpl implements IEditorialService {

    @Autowired
    private IEditorialRepository editorialRepo;

    @Autowired
    private ILibroRepository libroRepo;

    @Override
    @Transactional
    public EditorialResponseDTO crear(EditorialRequestDTO dto) {
        Editorial editorial = new Editorial(dto.nombre(), dto.pais());
        Editorial guardada = editorialRepo.save(editorial);
        return new EditorialResponseDTO(guardada.getId(), guardada.getNombre(), guardada.getPais());
    }

    @Override
    @Transactional(readOnly = true)
    public Optional<EditorialResponseDTO> obtenerPorId(Long id) {
        Optional<Editorial> opt = editorialRepo.findById(id);
        if (opt.isEmpty()) {
            return Optional.empty();
        }

        Editorial e = opt.get();
        return Optional.of(new EditorialResponseDTO(e.getId(), e.getNombre(), e.getPais()));
    }

    @Override
    @Transactional
    public int eliminar(Long id) {
        if (!editorialRepo.existsById(id)) {
            return 0; // 404
        }

        // Comprobación de integridad: verificar si tiene libros asociados
        long totalLibros = libroRepo.countByEditorialId(id);
        if (totalLibros > 0) {
            return -1; // 409 Conflicto
        }

        editorialRepo.deleteById(id);
        return 1; // 204 Éxito
    }
}

        Autor guardado = autorRepo.save(autor);
        return new AutorResponseDTO(guardado.getId(), guardado.getNombre(), guardado.getNacionalidad(), new ArrayList<>());

Qué hacen @Transactional y readOnly = true

Una transacción es un grupo de operaciones con la base de datos que se hacen todas o ninguna. Al crear un libro se guardan el libro, su ficha y sus relaciones con los autores; si algo falla a mitad, no queremos un libro a medias en la base. Con una transacción, o se confirma todo al final (commit) o se deshace todo (rollback).

Al poner @Transactional encima de un método del servicio, Spring hace tres cosas por ti:

  1. Abre la transacción al entrar en el método y la cierra al salir.
  2. Si el método termina bien, confirma los cambios. Si lanza una excepción, los deshace todos.
  3. Mantiene abierta la conexión con la base (la sesión de Hibernate) mientras dura el método. Por eso, dentro, puedes recorrer las relaciones LAZY del paso 12 (medico.getHospital().getNombre()) sin que salte LazyInitializationException. Y por eso la conversión a DTO se hace dentro del servicio: fuera, la sesión ya está cerrada.
Es como una compra en el súper: o pagas todo el carro y te lo llevas, o no pagas nada y lo dejas todo. Nunca sales con media compra.

@Transactional(readOnly = true) es la misma transacción, pero avisando de que el método solo lee. Hibernate no tiene que vigilar si cambias algo para guardarlo al final, así que va algo más rápido, y quien lea el código sabe de un vistazo que ese método no modifica nada. Se pone en los métodos que solo consultan (obtener, listar…); los que guardan, cambian o borran llevan @Transactional normal.

MétodoAnotaciónPor qué
crear, actualizar@TransactionalEscriben en la base: si algo falla, que se deshaga todo.
obtener, listar…@Transactional(readOnly = true)Solo leen, pero recorren relaciones LAZY al convertir a DTO: necesitan la sesión abierta.
Uno que solo llama a un método del repositorio (deleteById, countBy…, existsBy…)Puede no llevarlaLos métodos del repositorio ya traen su propia transacción, y no hay relaciones LAZY que recorrer.
Importa org.springframework.transaction.annotation.Transactional, la de Spring. Existe otra con el mismo nombre en jakarta.transaction, y esa no tiene readOnly: si VS Code te ofrece las dos, elige la de Spring.

Decisiones que conviene saber justificar

DecisiónPor qué
@Transactional en cada método, y readOnly = true en las lecturasEl mapeo a DTO recorre relaciones LAZY, así que la sesión debe seguir abierta. readOnly avisa de que solo se lee.
La conversión es un método privado mapearAResponseDTO dentro de LibroServiceImplLa regla pide que la conversión ocurra en el servicio, ya sea en métodos privados o en una clase Mapper. Aquí se elige método privado, sin librerías externas, porque solo Libro necesita ese mapeo completo. Si lo necesitaran varios servicios, un @Component Mapper evitaría repetir código.
