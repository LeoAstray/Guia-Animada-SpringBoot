20 El ejercicio: qué se pide y cómo se resuelve

El ejercicio no evalúa cuánto código sabes escribir, sino si sabes conectar las capas de un sistema Spring: RestController, IService, Service, JpaRepository, Entity, DTO y ResponseEntity. Antes de programar hay que poder dibujar y justificar el sistema: qué relación une cada entidad, qué viaja entre capas y qué código HTTP devuelve cada endpoint.

EntidadesRelaciónAnotación JPAAnalogía
Editorial y Libro1 : N@OneToMany / @ManyToOneUna mamá, muchos hijos
Autor y LibroN : M@ManyToManyMuchos niños, muchos juguetes
Libro y FichaLibro1 : 1@OneToOneCada niño, un carné

Las capas: RestController → IService → Service → JpaRepository → MySQL. Cada RestController inyecta su IService, y cada Service inyecta los repositorios que necesita, siempre con @Autowired.

El modelo de datos: cuatro Entities, cinco tablas

La «cuerda» (la clave foránea, FK) la lleva el niño pequeño de la mano de su mamá. En el N:M, como son muchos con muchos, hace falta una libretita aparte (LIBRO_AUTOR) que apunte «Ana juega con el coche». Esa libretita no es una Entity.

El orden en que se construye

  1. Proyecto y configuración (sección 21).
  2. Misión 1: decidir las relaciones y escribir las Entities (22).
  3. Repositorios (23).
  4. Misión 2: los DTO (24).
  5. Servicios con la conversión Entity y DTO (25) y controladores con los códigos de estado (26).
  6. Misión 5: provocar las trampas (27).
  7. Ampliación: validación con @Valid (28).
  8. Probar (29).
